## 一、项目画像（一句话 + 标签）

**一句话**：基于 React 19 + Vite 8 + Electron 41 的「本地闭环多端推理矩阵」监控运维看盘系统，以 PWA Web（GitHub Pages）+ 三平台桌面端双形态交付，内置 AI 诊断建议、巡检、数据库/主机文件管理、音乐空间等 40+ 功能页，带 Ghost Mode 免密管理员登录的演示友好型单体前端应用。

**核心标签**：`React 19` `Vite 8` `TypeScript strict` `Electron 41` `PWA` `Hash Router` `Radix UI + MUI 9 + Tailwind 4（三套并存）` `Supabase(可降级 Mock)` `Zustand` `Recharts` `CodeMirror 6` `Vitest 5` `pnpm workspace` `Cyberpunk 主题` `中英双语`

## 三、深度维度分析（现状 / 问题 / 影响）

### 3.1 架构合理性 —— 结论：B+
- **现状**：清晰的 App 分层（components/hooks/lib/stores/types），Hash Router 适合 Pages 部署，vendor 手工分包 10 组，PWA + Electron 双壳。
- **问题**：① `routes.ts` 40+ 页面全部静态导入（注释自述为 Figma Make 沙箱妥协），代码分割为零；② 三套 UI 体系并存（Radix+MUI+Tailwind），MUI 9 的 Emotion 运行时与 Tailwind 静态方案混用；③ `SupabaseClientWrapper` 手写 mock 查询构建器，真假数据源行为差异大（mock 的 select 永远 resolve 空数组）。
- **影响**：首屏 JS 体积必然触顶（chunkSizeWarningLimit 被调至 400KB 佐证）；mock 模式"查什么都返回成功空数据"，演示与真实行为脱节，易误导决策。

### 3.2 代码质量 —— 结论：A-
- **现状**：strict TS 零错误（实测 `pnpm type-check` 通过）；ESLint 0 error；文档头部规范（@file/@version）强制执行（check-headers 脚本）。
- **问题**：`any` 231 处（43 条 lint 警告集中于此）；console.log 9 处残留；`pnpm lint:fix` 在 CI 中直接跑（自动修复掩盖问题而非暴露）。
- **影响**：类型安全网存在局部破洞；CI lint 步骤形同虚设。

### 3.3 技术债务 —— 结论：B（量大但多为清理级）
1. **AGENTS.md 严重过期**：React 19.2.4→实际 19.3.0、Vite 7.3.1→8.3.4、Electron 28→41、Supabase 2.98→2.117、MUI 7.3.8→9.4、Tailwind 4.2.1→4.3.3、lucide 0.576→1.48；`pnpm test` 说成"运行一次"实际是 watch 模式。
2. **双 lockfile**：package-lock.json（585KB，npm）与 pnpm-lock.yaml 并存，主策略 pnpm，npm lockfile 是僵尸。
3. **构建产物入库**：electron/dist-electron/*.js(+map)、test-report.txt（145KB）、tsconfig.node.tsbuildinfo 被 git 跟踪。
4. **仓库卫生**：根目录散置 fix_component_imports.py、test.html、diagnose.html、react-test.html；`workflows/ci.yml` 是与 .github 不同的错位副本；`.archive/` 留存。
5. **Electron 层实现债**：自动更新未接线（托盘"检查更新"只弹对话框）；打包后托盘/窗口图标路径失效（public→resources 映射与代码中 `../public/icons` 不符）；`electron/main.js`（过期 CJS）与 `electron/dist-electron/main.js`（ESM）两份编译产物并存。

### 3.4 性能风险 —— 结论：B
- **现状**：esbuild 压缩、vendor 分包、optimizeDeps 预热、Lighthouse CI 预算门禁（已配 lighthouserc.json）。
- **问题**：① 无代码分割 + MUI/Recharts/CodeMirror 全量进主图 → 首屏加载是最大风险点（Lighthouse TBT/FCP 预算很可能在弱网失守）；② 测试环境 jsdom 创建 78 次占 48% 耗时（vitest 官方提示可用 pool:'vmThreads'/isolate:false 优化，全量 2639 用例 110s+）。
- **影响**：Web 端弱网体验差；测试反馈环偏长。

### 3.5 安全风险 —— 结论：C+（本项最需要管理层关注）
| # | 问题 | 位置 | 严重度 |
|---|---|---|---|
| 1 | **Ghost Mode：免凭证获得 admin 会话**，且 ghostSignIn 无条件导出，登录页可点 | src/app/lib/supabaseClient.ts:289 | 高（演示后门必须在生产关闭） |
| 2 | **Mock 账号默认密码硬编码兜底** `"change_admin_password"`/`"change_dev_password"`，env 未配置时生效 | supabaseClient.ts:28,32 | 高 |
| 3 | 会话 token 明文存 localStorage（XSS 即可窃取），无 HttpOnly/SameSite 选项；token 用 `Math.random` 生成（mock） | supabaseClient.ts 全文 | 中 |
| 4 | macOS 构建 `NSAllowsArbitraryLoads: true` —— ATS 全关，允许任意明文 HTTP | package.json build.mac | 中 |
| 5 | Electron 层做得规范：nodeIntegration:false + contextIsolation:true + 窗口拦截仅放行 http(s) 外部打开 | electron/main.ts:17-21,42 | ✅ 正面 |
| 6 | 依赖审查 CI（GPL/AGPL 拒绝 + high 漏洞阻断）已启用 | ci.yml dependency-review | ✅ 正面 |
| 7 | dangerouslySetInnerHTML 仅 1 处且为 chart 样式注入（shadcn 模式），低风险 | ui/chart.tsx:115 | 低 |

### 3.6 可维护性 —— 结论：B+
- 正面：docs/ 目录 16 个分类知识库 + 4 个 API/组件参考 + db-schema.sql；自研审计脚本三位一体；i18n 双语言完备。
- 问题：文档与代码版本漂移（AGENTS.md 为证）；43 个路由平铺无模块边界，新增功能的归属规则缺失；排障靠 console（无 Sentry 类前端监控，**待确认**是否有外部监控）。

## 四、测试验证执行（实测结论）

### 4.1 门禁实测结果
| 门禁 | 命令 | 结果 |
|---|---|---|
| 类型检查 | `pnpm type-check` | ✅ 0 错误 |
| 静态检查 | `pnpm lint` | ⚠️ 0 错误 / 43 警告（全为 no-explicit-any） |
| 单测（2 分片） | `vitest run --shard=1/2` / `2/2` | ❌ 2639 用例：2637 通过、**2 失败、1 个测试文件加载失败** |

### 4.2 失败项根因
1. `rf-phase2.test.ts` RF-011 ×2（routes.ts 导出 router / 含 * 通配路由）：`await import("../routes")` 在 jsdom 下 10s 超时——routes.ts 静态引入全部 40+ 重组件（MUI/Recharts/CodeMirror），测试环境扛不住。**测试写法与架构决策共同导致**。
2. `AISuggestionPanel.test.tsx` 整文件加载失败：`vi.mock` 嵌套在 describe 内，Vitest 5 严格提升校验直接拒绝。**该组件全部用例静默跳过 = 覆盖率黑洞**。

### 4.3 建议补测清单（优先级 P0→P2）
| 优先级 | 用例 | 正向 | 反向/边界 | 预期 |
|---|---|---|---|---|
| P0 | 认证流 | admin/dev 登录成功进大盘 | 错误密码拒绝；过期会话清理；Ghost 开关关闭后不可进入 | 会话 8h，过期强制回登录页 |
| P0 | Ghost Mode 生产开关 | dev 环境可 ghost | **生产构建 ghostSignIn 不可达** | 需新增 env 开关用例 |
| P1 | WebSocket 数据流 | connected 状态渲染实时数据 | 断连→reconnecting→simulated 降级三态 UI | 各态有明显指示 |
| P1 | 巡检闭环 | 创建计划→执行→生成报告 | 空计划、重复执行、中断恢复 | 报告数据与执行日志一致 |
| P1 | 数据编辑器 | 编辑→撤销→保存 | 并发修改冲突、非法 SQL/类型 | Undo 状态机正确 |
| P2 | PWA 离线 | 断网启动、队列同步 | 缓存版本过期升级 | 不白屏、可恢复 |
| P2 | 兼容性 | Chrome/Edge/Safari 最新两版；Electron 三平台冒烟 | 1024×768 最小窗口 | 无布局崩坏 |

### 4.4 通过标准建议
- 门禁：type-check 0 错、lint 0 错、测试 100% 通过方可合并（当前基线：先修 2 失败 + 1 套件）
- 覆盖率：维持 CI coverage-gate phase1 现状，逐步上调（当前阈值约 10%）
- Lighthouse：lighthouserc.json 预算为硬门禁（PR 阻断），保持
- 失败判定：P0 用例任一失败 = 阻断发布；P1 失败允许带 issue 编号合并

## 六、优化优先级与落地建议

**短期（1 周内，止血）**
1. 修复测试基线：AISuggestionPanel 的 vi.mock 提升到顶层；rf-phase2 改为静态分析 routes 源码文本断言（避开全量 import）或给 routes 导入测试单开长超时 + 单 worker。
2. 给 Ghost Mode 与 Mock 认证加 `VITE_ALLOW_GHOST` / 环境守卫，生产构建默认关闭；删除默认密码兜底（未配置 env 时登录直接报错）。
3. Electron 构建二选一：接入 vite-plugin-electron（推荐，依赖已装）或把 electron tsconfig 改为真正产出并修正 main 字段；删除过期 electron/main.js。

**中期（2-4 周）**
4. routes.ts 恢复 React.lazy 代码分割（Web 构建）；Electron 壳可用静态版单独配置，两全。
5. 仓库大扫除：删 package-lock.json、清理入库产物（git rm --cached + .gitignore）、根目录散件归档到 scripts/或删除、删除 workflows/ 错位目录。
6. 刷新 AGENTS.md 与 docs/ 中所有版本号（建议从 package.json 自动生成）。
7. any 清零行动：43 处 lint 警告逐文件修复，console.log 换 electron-log/统一 logger。

**长期（1-2 月）**
8. 收敛 UI 体系：MUI 9 与 Radix 组件存量盘点，新代码只允许 Radix+Tailwind，MUI 逐步替换。
9. 安全加固：token 存储策略升级（至少加 SameSite 说明与 XSS 审计）、macOS ATS 白名单化（去掉 NSAllowsArbitraryLoads）。
10. 测试性能优化（vmThreads/isolate）+ 覆盖率阈值阶梯上调至 30%。
