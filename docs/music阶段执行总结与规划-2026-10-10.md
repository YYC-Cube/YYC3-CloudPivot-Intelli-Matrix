### 3.2 数据链路与读写分离

- **主库**：Mac pg15 `:5433`（`yyc3_music`，trust 认证）——154 首 approved + 14 专辑
- **备库**：NAS pg15 `:5433`，流复制 lag=0（实测复核同步）
- 154 条 `file_path` 已切换为 NAS 路径并验证复制到位；11 条旧种子（status=deleted）不动
- Mac pg 开启 `listen_addresses='*'` + hba 放行 Tailscale 网段（`100.64.0.0/10`），NAS 侧经 Tailscale 可写主库（实测从 NAS 连接返回 1）
- 写路径注意：备库只读，所有写必须走主库；`musics.status` CHECK 约束仅允许 draft/pending/approved/rejected/deleted

### 3.3 music-api 服务（NAS 容器）

- **形态**：Fastify 5 单容器 `yyc3-music-api`，代码在 NAS `/Volume1/yyc3_hd/music-api/`（仓库 `music-api/` 目录为源）
- **接口**：`/healthz`（+ `/api/music/healthz` 别名）、`/api/music/albums`、`/api/music/tracks?album=&q=`、`/api/music/stream/:id`（Range 206 + 目录穿越防护）、`POST /api/music/tracks/:id/play`（写转发，主库离线返回 503）
- **读写分离**：读 = NAS 本机备库（LAN 低延迟）；写 = 经 Tailscale 转发 Mac 主库
- **实测**：healthz ok / 中文过滤搜索 / 整流 200 / Range 206 精确字节 / play_count 递增 / 穿越拦截 ✅

### 3.4 前端曲库接入

### 3.5 顺手修复的基建问题（4 个）

| 问题 | 根因 | 解法 |
|---|---|---|
| `pnpm dev` 必崩 | vite-plugin-electron serve 期 spawn electron 二进制，而 pnpm 默认不执行其 postinstall（二进制缺失） | 插件仅构建期/`ELECTRON_ENABLE=true` 加载；`package.json` 加 `pnpm.onlyBuiltDependencies: ["electron"]` 根治 |
| 容器读媒体 EACCES | TOS 启用 SMACK（lsm 含 smack/ima/evm），POSIX 权限形同虚设，仅 root 与属主 uid 可读 | compose `user: "501:101"`（媒体属主），免 root |
| 备库拒连 `no pg_hba entry 172.24.0.2` | docker bridge 回环访问宿主 IP 不做 SNAT；NAS 侧 sudo 受 root-squash 限制改不了 hba | `network_mode: host`，源 IP 落已有信任网段 |
| 前端 healthz 404 | 服务端健康检查在 `/healthz`，前端基址是 `/api/music` | 服务端补别名路由（原路径保留给容器探针） |
